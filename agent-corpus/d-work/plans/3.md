# Plan #3 — P3 inference: one provider interface and adapters; a dated price comparison; the cheapest that passes P2; the key a saved credential

base commit: 880a37f7e49019c0117c63c127c0c028d550b522

## Definition of done (proposed: the row's title and the phase plan's P3, `site/lean-canvas/prompt-therapy.md` in dyad-system)
1. One provider interface with real adapters behind it, beside the fake one.
2. A dated price comparison, with its sources.
3. The chosen provider is the cheapest one that passes P2's adversarial set, by `dmc:provider-choice`.
4. The key is a saved credential: never a file, never in the chat.
All four are judged together by #3's done-`Y`. The work runs under `crafts/prompt-therapy/playbooks/provider.md`.

## Intent as read
A real model words the walk's replies. The engine keeps choosing every state, and the never-rule checks keep running
on every outgoing line, whatever the model writes. The bar is P2's 42 members, the same set the fake provider passes.

## Acts that reach outside this repository (each named here so the plan-`Y` covers it in words)
- **The key.** One credential for `api.anthropic.com`, asked through the credential request form. You enter it there;
  I never see or store it.
- **Sending content to the provider.** The adversarial set is sent to the provider's API: your public prompts, read
  at the pin, and the 28 variants written for the tests, which name only invented people. No user conversation
  exists, so none is sent. This is the one act of sending outside the dyad this plan asks for.
- **Spend.** At most **US$10** in total across every evaluation run, stopped before the bound. The estimate is about
  $0.05 on Haiku and about $3 on Opus for one full pass, at the cached list prices below.
- **One reversible host action.** `pip install anthropic==2.8.0` into this session's Python (undo: `pip uninstall
  anthropic`), with a change-log row.

## Candidates and the comparison
- **Candidates:** the current Claude models through the official Anthropic SDK (`anthropic` 2.8.0: MIT, on PyPI,
  within `import-licenses` and `import-support`):

  | model | input $/1M | output $/1M |
  |---|---|---|
  | `claude-haiku-5-5` | $0.10 | $0.50 |
  | `claude-sonnet-5-5` | $2 | $10 |
  | `claude-opus-5-5` | $4 | $20 |

- **Prices** are the claude-api skill's table cached on 2026-11-03. They are re-read from the live pricing page when
  the comparison is written, and the comparison is dated and cites both sources.
- **Terms.** `dmc:provider-choice` lets a provider be chosen only if its terms keep nothing it is sent beyond the
  request. The API's data-retention terms are read and quoted in the comparison. If they keep request data longer
  (a retention window), the record's outcome is **none-passes on terms**. In that case I report it and ask: either
  arrange a zero-retention agreement, or change the record, which is your decision and its own row. I do not pick a
  provider past that record.

## Mutation
**Craft zone** (`crafts/prompt-therapy/`), one PR:
1. `scripts/provider.py` gains `AnthropicProvider(model, effort)`.
   - The model writes only the framing sentence of a reply.
   - The adapter appends every option list verbatim and always opens the greeting with the no-therapy line, so a
     model can never drop an option or the disclaimer.
   - The system prompt states the three never rules. `max_tokens` is bounded, refusal stop reasons are handled, and
     the key is read from the saved credential.
   - `FakeProvider` is unchanged and stays the default.
2. `scripts/evaluate.py`: runs the adversarial set (P2's `drive`, shared) against one adapter. It prints, per member,
   pass or fail with the reason, then the tokens used and the cost at the dated prices, and it refuses to run past the
   spend bound. It runs by hand only, never in the suite.
3. Tests that run offline:
   - `tests/test_provider.py`: the adapter with a recorded response, where options and the disclaimer survive a model
     that drops them;
   - `tests/test_evaluate.py`: the cost arithmetic and the spend refusal.
4. `infrastructure_contrib.md`: the manifest row for `anthropic` (a library row, profile `operating`, replacement:
   another provider's SDK). `manifest_rules_contrib.txt`: `anthropic: import:anthropic`.
5. `VERSION` 0.3.0 → 0.4.0. `README.md` names the adapters and the evaluation command.

## Falsification
- "Raw HTTP keeps the kernel stdlib-only": refuted. Rule-13 prefers import over authoring, the official SDK fits the
  import criteria, and one manifest row declares it.
- "The cheapest model must be chosen": survives, scoped. Cheapest among those that pass and whose terms are
  acceptable; price never decides past a failure (`dmc:provider-choice` precedence).
- "A real model can still diagnose": survives, and that is the point. The engine's outgoing check replaces any such
  line and counts a breach, and P2 fails any breach. So a model that diagnoses fails the set and is not chosen.
- "Other vendors may be cheaper": survives as a counter. Each one adds a key, terms and an adapter. The interface
  admits them as later rows; this row compares one vendor's three tiers.
- "Sending the test set is publishing": refuted, scoped. It is sent to a processor under its terms, not published,
  and it carries only public prompts and invented text. It is still named here and asked, because the spawn brief
  says nothing is sent outside the dyad without your words.
- Nothing depends on the paused `specs` work.
